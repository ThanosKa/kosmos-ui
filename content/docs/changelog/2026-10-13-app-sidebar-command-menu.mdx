---
title: Changed App sidebar, Command menu and Sidebar for icon mode and the analytics sample
description: App sidebar collapses to icons and shows the pages of a product analytics app, Command menu searches its projects, and Sidebar content scrolls in a Scroll area.
date: 2026-10-13
---

App sidebar and Command menu now show the same fictional product analytics app as the other blocks. Some props and values changed, so check your code after you run `shadcn add` again.

- **[App sidebar](/docs/blocks/app-sidebar)**: collapses to a column of icons by default (`collapsible="icon"`, or `"offcanvas"` for the old behavior), and `SidebarProvider` remembers the state between visits. Each page names itself in a tooltip, and the workspace mark and the user's avatar stay in the column. The search button is a sidebar item, so it shows "Search" in a tooltip too. The account menu is now the user menu: the action `account-settings` is now `preferences`, labelled Preferences, and the trigger reads "…, user menu". The sample pages are Overview, Projects, Events, Users, Revenue and Roadmap, with the saved views Scale plan and Trials, and `activeItem` defaults to `projects`. The block no longer lists Button among its dependencies, because it comes with Sidebar.
- **[Command menu](/docs/blocks/command-menu)**: the sample lists the projects with their domain and status, the actions New roadmap item and Invite teammate, and the app sidebar's pages. Its second lists pick a teammate (Show roadmap items assigned to…) and switch workspace, in place of Change status and Assign owner. It still opens and closes without animation.
- **[Page header](/docs/blocks/page-header)**: the primary action shows only when you pass `onNew`, the same way the More actions menu needs `onAction`, so a page without one no longer shows a button that does nothing.
- **[Sidebar](/docs/components/sidebar)**: `SidebarContent` scrolls in a Scroll area, so an edge with items hidden past it fades out. `render`, `className` and the other props go to the element that scrolls, which now holds the groups in a block inside it, so flex or gap classes there no longer reach them. In icon mode the first child of `SidebarMenuButton` stays visible, so a workspace mark or an avatar in a menu trigger keeps showing, and the scrollbar hides while the fade still marks the overflow. A count's screen reader label no longer widens a collapsed sidebar. Sidebar now brings Scroll area with it.
- **[Scroll area](/docs/components/scroll-area)**: the new `viewportRender` renders the element that scrolls as another element, such as a `<nav>`.
