The scroll trigger follows the scroll-linked text reveal of [Magic UI](https://github.com/magicuidesign/magicui) (MIT), restyled to the Kosmos tokens. Its copyright line lands next to the component, in `LICENSE-MAGIC-UI`.

## Usage

```tsx
import { TextReveal } from '@/components/ui/text-reveal';
```

```tsx
<h1>
  <TextReveal>Dashboard UI with the details already done</TextReveal>
</h1>
```

The words are plain text in the markup, so search engines, screen readers and a browser without JavaScript get the whole title. By default the entrance is a CSS transition from the `starting` style, so it plays on the first paint, with no hydration wait. Pass a string: a title with markup inside cannot be split into words.

For a section further down the page, set `trigger="view"`: text below the fold waits hidden and plays once, the first time it scrolls into view; text already on screen stays put. Each word takes 500ms and starts 120ms after the one before, so a title of seven words is in after about 1.2s. The stagger shortens for a long text, so the last word starts within 900ms. The entrance is a CSS animation, so a theme change that switches transitions off cannot cut it short.

For a statement that should be read at the reader's pace, set `trigger="scroll"`. Each word goes from faint to full as the text scrolls up the screen, and fades back when the reader scrolls up again. It needs no tall section and no sticky wrapper: the text keeps its place in the page. Use it for one closing statement, not for every title.

## Accessibility

Nothing is hidden from assistive technology and the text never changes. Under reduced motion the entrances fade in together, with no blur and no rise, and the scroll trigger shows the whole text at full strength.

## API

TextReveal is a `<span>` and accepts all of its props. It wraps no Base UI part.
