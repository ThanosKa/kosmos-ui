## Usage

```tsx
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
  SidebarGroupLabel,
  SidebarHeader,
  SidebarInset,
  SidebarMenu,
  SidebarMenuBadge,
  SidebarMenuButton,
  SidebarMenuItem,
  SidebarProvider,
  SidebarResizeHandle,
  SidebarTrigger,
} from '@/components/ui/sidebar';
```

```tsx
<SidebarProvider>
  <Sidebar collapsible="icon">
    <SidebarHeader>Acme</SidebarHeader>
    <SidebarContent render={<nav aria-label="Main" />}>
      <SidebarGroup>
        <SidebarGroupLabel>Workspace</SidebarGroupLabel>
        <SidebarMenu>
          <SidebarMenuItem>
            <SidebarMenuButton href="/inbox" isActive tooltip="Inbox">
              <Inbox />
              <span>Inbox</span>
              <SidebarMenuBadge>12</SidebarMenuBadge>
            </SidebarMenuButton>
          </SidebarMenuItem>
        </SidebarMenu>
      </SidebarGroup>
    </SidebarContent>
    <SidebarFooter>…</SidebarFooter>
  </Sidebar>
  <SidebarResizeHandle />
  <SidebarInset>
    <header>
      <SidebarTrigger />
    </header>
    …
  </SidebarInset>
</SidebarProvider>
```

`SidebarProvider` wraps the whole app shell and fills the screen. The sidebar sticks to the top while the page scrolls, and its content scrolls on its own between the header and the footer, in a [Scroll area](/docs/components/scroll-area): an edge with items hidden past it fades out.

From 768px up the sidebar sits beside the page. Below that it leaves the layout, `SidebarTrigger` opens it as a drawer from the left edge, and a click on a link closes the drawer. `mobileBreakpoint` moves that point.

## Collapsing

`SidebarTrigger`, `⌘B` (`Ctrl+B` on Windows and Linux) and the resize handle collapse the sidebar beside the page. `collapsible` on `Sidebar` sets where it goes:

| `collapsible` | Collapsed |
| --- | --- |
| `offcanvas` (default) | The sidebar slides off to the edge and gives the page its space. |
| `icon` | A 48px column of icons stays. The labels, counts and group labels fade out, the active item keeps its highlight, and each item shows its `tooltip` on hover and keyboard focus. |

In icon mode, give every `SidebarMenuButton` a `tooltip` with its name. The button's first child stays visible, so put the icon first, or a workspace mark or an avatar in a menu trigger; the label and count after it fade. Your own content in the header or footer can fade with it: `group-data-[collapsible=icon]/sidebar:opacity-0` hides a workspace name and leaves its logo, and `motion-safe:group-data-[state=expanded]/sidebar:delay-(--transition-duration-fast)` holds it back on expand until the column is wide enough, as in the example at the top. On phones the drawer always shows the full sidebar.

The sidebar remembers whether it was collapsed. It saves the state in local storage under `storageKey` (`'sidebar-state'`), and a small script puts it back before the page paints, so a collapsed sidebar never flashes open on reload. Give each sidebar on a page its own key, or pass `storageKey={false}` to keep nothing. `keyboardShortcut` changes the key, and `false` turns the shortcut off.

## Resizing

`SidebarResizeHandle` sits on the sidebar's edge, between `Sidebar` and `SidebarInset`. It is a window splitter:

| Input | Action |
| --- | --- |
| Drag | Resizes between `minWidth` and `maxWidth`. Dragging below halfway from `minWidth` to the collapsed width collapses the sidebar, to the edge or to icons. |
| Double click | Returns to `defaultWidth`. |

It also takes focus and resizes from the keyboard: see [Keyboard](#keyboard).

The width resets on every visit. To keep it, control `width` and save it, as in the example below. A controlled `open` is yours to save too: the sidebar stores nothing while `open` is controlled.

## Motion

The sidebar collapses and reopens by easing its width over 300ms with `smooth-in-out`; in icon mode the labels fade out in 150ms as it narrows. While you drag or use the arrow keys, the width follows without easing. Under reduced motion the sidebar (in icon mode, its labels) fades out, then the width changes at once; on reopen the width comes back first and the content fades in.

### Parts

Each part is a styled element you can rearrange. `useSidebar()` reads and sets the state from any component inside the provider: `open`, `setOpen`, `openMobile`, `setOpenMobile`, `toggleSidebar`, `isMobile`, `collapsible`, `width` and `setWidth`.

| Part | What it is |
| --- | --- |
| `SidebarProvider` | Holds the open state and the width, and lays the sidebar and the page out side by side. |
| `Sidebar` | The sidebar surface beside the page, or the drawer on phones. `collapsible` sets where it collapses to; `label` names the drawer for screen readers. |
| `SidebarResizeHandle` | The drag handle on the sidebar's edge. Leave it out for a fixed width. |
| `SidebarTrigger` | A 30px secondary icon button that opens and closes the sidebar, or the drawer on phones. Beside the page, its tooltip shows the keyboard shortcut. |
| `SidebarInset` | The page beside the sidebar. Renders `<main>`; pass `render={<div />}` when your layout already has one. |
| `SidebarHeader` | The top of the sidebar, for the product or workspace name. A full-width line sets it apart. |
| `SidebarContent` | The scrolling middle, a Scroll area whose edges fade while items hide past them. `render` and the other props go to the element that scrolls: `render={<nav aria-label="Main" />}`. |
| `SidebarFooter` | The bottom of the sidebar, for the user menu or help links, below a full-width line. |
| `SidebarSeparator` | An inset line, for a break inside a group. The header, the groups and the footer draw their own lines. |
| `SidebarGroup` | A section with a label and a menu. Every group after the first sits below a full-width line. |
| `SidebarGroupLabel` | The small uppercase heading of a group. `render={<h2 />}` makes it a heading. |
| `SidebarMenu` | The list of items in a group. Renders `<ul>`. |
| `SidebarMenuItem` | One item. Renders `<li>`. |
| `SidebarMenuButton` | The clickable row of an item: a link with `href`, a button without it. `isActive` marks the current page: idle items are muted, and the active one sits on the flat hover fill with its label and icon in `active-foreground`, ink by default. Put the label in a `<span>` so it truncates. |
| `SidebarMenuBadge` | A count at the end of an item, in a small pill. |

## Keyboard

| Key | Action |
| --- | --- |
| `⌘B` or `Ctrl+B` | Anywhere on the page: collapses or reopens the sidebar beside the page at once, without the width easing. It does nothing on phones, where the trigger opens the drawer. Set by `keyboardShortcut`. |
| `ArrowRight` or `ArrowLeft` | On the resize handle: widens or narrows the sidebar by 16px. A collapsed sidebar reopens on the key that widens it. In a right-to-left layout, the keys swap. |
| `Shift` + `ArrowRight` or `Shift` + `ArrowLeft` | Resizes by 64px. |
| `Home` or `End` | On the resize handle: sets the width to `minWidth` or `maxWidth`, and reopens a collapsed sidebar. |
| `Enter` | On the resize handle: collapses or reopens the sidebar at once, without the width easing. |
| `Enter` or `Space` | On `SidebarTrigger`: opens or closes the sidebar, or the drawer on phones. |
| `Escape` | On phones: closes the drawer and puts focus back on the trigger. |

A sidebar collapsed to the edge is out of the tab order, so `Tab` skips its links until it opens again. In icon mode the icons stay in the tab order, and each one shows its name as it takes focus.
