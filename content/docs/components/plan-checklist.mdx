## Usage

```tsx
import { PlanChecklist, type PlanStep } from '@/components/ui/plan-checklist';
```

```tsx
const steps: PlanStep[] = [
  { id: 'events', label: 'Pull the last 7 days of events', status: 'done', detail: '6,838,800 events' },
  { id: 'quota', label: 'Flag projects near their quota', status: 'running', detail: '40%' },
  { id: 'summary', label: 'Draft the summary for Lena Park', status: 'pending' },
];

<PlanChecklist title="Prepare the weekly summary for Acme" steps={steps} />;
```

The header shows the title and how many steps are done, such as "1 of 3". Click it to open or close the list. Each step leads with a status mark:

| Status | Mark | Label |
| --- | --- | --- |
| `pending` | Dashed circle | Muted |
| `running` | Spinner | Full ink, medium weight |
| `done` | Green check | Muted |
| `error` | Red cross | Full ink. Put the reason in `detail`. |
| `skipped` | Slashed circle | Muted and struck through |

Update `steps` as the agent works. When the last step is done, the list closes and the header icon turns into a green check. Set `collapseWhenDone={false}` to keep it open.

Screen readers hear each step's status after its label. A hidden live region announces progress, such as "Step 3 of 5 done", and names a step when it fails.

When the reduced motion setting is on, the list fades in and out instead of growing, and the running spinner pulses instead of turning.

## Examples

### Approve before running

Pass buttons to `actions` to show them under the list, for example to run or edit a proposed plan. Swap them as the run goes on, as in the demo above, which turns "Run plan" into "Reset".

### A failed step

An `error` step keeps its label in full ink and its reason in `detail`. Mark the steps that will not run as `skipped`, and offer a way on in `actions`.

<ComponentPreview name="plan-checklist-failed" />

### Inside another surface

Set `surface="none"` to drop the card, so the checklist sits flat inside a message, a panel or a run timeline.

<ComponentPreview name="plan-checklist-flat" />

### Controlled

Pass `open` and `onOpenChange` to open and close the list from your own state. When every step is done, `onOpenChange` is called with `false`, unless `collapseWhenDone` is `false`.

## Keyboard

| Key | Action |
| --- | --- |
| `Tab` | Moves to the header, then to the actions when the list is open. |
| `Enter` or `Space` | Opens or closes the list. |
