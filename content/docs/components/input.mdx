## Usage

```tsx
import { Input } from '@/components/ui/input';
```

```tsx
<Input type="email" name="email" aria-label="Email" placeholder="name@company.com" />
```

An Input on its own needs an `aria-label`. In most forms, put it in a [Field](/docs/components/field) instead, which gives it a visible label and connects the help text and error to it.

On small screens the text is 16px, so iOS doesn't zoom the page when the input gets focus. From the `sm` breakpoint up it's 14px, like the rest of the interface.

### Types

Input passes `type` to the native `<input>`, so the browser brings its own keyboard, autofill and picker for each type. Add `tabular-nums` to number inputs so the digits line up.

<ComponentPreview name="input-types" />

### Beside a button

Input has the same height as a medium Button, so the two line up in a row.

<ComponentPreview name="input-with-button" />

### Invalid

Set `invalid` on the Field and add a FieldError. The input gets a red ring and `aria-invalid`, and screen readers read the error with it. Outside a Field, set `aria-invalid` on the Input yourself.

<ComponentPreview name="input-invalid" />

### Disabled and read-only

A disabled input can't be focused and isn't sent with the form. Use `readOnly` for a value people should be able to select and copy but not change.

## API

Input wraps the [Base UI Input](https://base-ui.com/react/components/input) and accepts all of its props and all `<input>` props.
