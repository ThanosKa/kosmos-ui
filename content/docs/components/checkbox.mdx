## Usage

```tsx
import { Checkbox } from '@/components/ui/checkbox';
import { Field, FieldLabel } from '@/components/ui/field';
```

```tsx
<Field name="summary" orientation="horizontal">
  <Checkbox />
  <FieldLabel>Weekly summary</FieldLabel>
</Field>
```

Put the Checkbox first in a horizontal [Field](/docs/components/field), with its FieldLabel beside it. The label names the checkbox, and clicking it ticks the box. Without a Field, wrap the Checkbox and its text in a `<label>`, as in the demo above, or give it an `aria-label`.

A ticked checkbox submits `on`, or its `value` when you set one. An unticked one submits nothing, as a native checkbox does.

## Keyboard

| Key | Action |
| --- | --- |
| Space | Ticks or unticks the focused checkbox |
| Tab | Moves to the next control |

## Examples

### With a description

Wrap the label and description in a FieldContent. The checkbox stays on the label's first line, however far the text wraps.

<ComponentPreview name="checkbox-with-label" />

### Group with a parent

A parent checkbox ticks or unticks a whole list and shows the mixed state when only part of it is ticked. Wrap the list in Base UI's `CheckboxGroup` with every child value in `allValues`, mark the parent `parent`, and give each option a FieldItem so it gets its own label.

<ComponentPreview name="checkbox-group" />

### Invalid

Set `invalid` on the Field and put the message in a FieldError. A `required` checkbox also fails the browser's checks until it is ticked.

### FieldItem

FieldItem comes with [Field](/docs/components/field). It holds one option of a group, the control beside its own FieldLabel, while the Field names the whole group and carries its error.
