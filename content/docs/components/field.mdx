## Installation

<ComponentInstall name="field" />

Field installs [Input](/docs/components/input) with it, the control most fields hold. Add the other controls you need on their own.

## Usage

```tsx
import { Field, FieldDescription, FieldError, FieldLabel } from '@/components/ui/field';
import { Input } from '@/components/ui/input';
```

```tsx
<Field name="email">
  <FieldLabel>Email</FieldLabel>
  <Input type="email" required />
  <FieldDescription>We send invoices to this address.</FieldDescription>
  <FieldError>Enter an email address with a domain, such as name@company.com.</FieldError>
</Field>
```

Put one control in each Field. The Field connects the parts for you:

- FieldLabel becomes the control's accessible name.
- FieldDescription and FieldError are read after it, through `aria-describedby`.
- An invalid Field sets `aria-invalid` on the control.
- A disabled Field disables the control and dims the label and description.

The control can be [Input](/docs/components/input), [Textarea](/docs/components/textarea), [Select](/docs/components/select), or any Base UI control, such as Checkbox, Switch or Slider.

## Examples

### Validation

Field runs the browser's own checks (`required`, `type`, `minLength`, `pattern`) and shows a FieldError when one fails. `validationMode="onBlur"` checks when focus leaves the control; the default checks on submit. Give each check its own message with `match`. Type a name without a domain in the demo at the top, then leave the field.

```tsx
<Field name="email" validationMode="onBlur">
  <FieldLabel>Email</FieldLabel>
  <Input type="email" required />
  <FieldError match="valueMissing">Enter your email address.</FieldError>
  <FieldError match="typeMismatch">Enter an email address with a domain, such as name@company.com.</FieldError>
</Field>
```

For your own rules, pass `validate`: a function that gets the value and returns an error message, or nothing when the value is fine.

### Errors from your app

When a form library or the server decides the value is wrong, set `invalid` on the Field and put the message in a FieldError. It shows for as long as `invalid` is true.

### With a Select

Select's trigger is a button, so give its label `nativeLabel={false}` and `render={<div />}`. It still names the Select, without a native label's click forwarding.

`orientation="horizontal"` puts the control beside a FieldContent that holds the label and description, as in a settings list. Checkbox and Switch use it too, with the control first.

### FieldContent, FieldDescription, FieldItem

FieldContent is a plain `<div>` that stacks the label, description and error in a horizontal Field. FieldDescription is the help text under the control. FieldItem wraps one option of a checkbox or radio group with its own label and description.
