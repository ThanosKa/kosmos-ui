The block brings [Tabs](/docs/components/tabs), [Input](/docs/components/input), [Dropdown menu](/docs/components/dropdown-menu) and [Button](/docs/components/button) with it, and lands in `components/page-header.tsx`.

## Usage

```tsx
'use client';

import { useState } from 'react';
import { PageHeader } from '@/components/page-header';
import { SidebarTrigger } from '@/components/ui/sidebar';

export default function ProjectsPage() {
  const [tab, setTab] = useState('all');
  const [query, setQuery] = useState('');
  const [filters, setFilters] = useState<string[]>([]);

  const shown = projects.filter(
    (project) =>
      (tab === 'all' || project.status === tab) &&
      project.name.toLowerCase().includes(query.toLowerCase()) &&
      (filters.length === 0 || filters.includes(project.plan)),
  );

  return (
    <PageHeader
      leading={<SidebarTrigger />}
      tab={tab}
      onTabChange={setTab}
      query={query}
      onQueryChange={setQuery}
      filters={filters}
      onFiltersChange={setFilters}
    >
      {/* the list of shown projects */}
    </PageHeader>
  );
}
```

`SidebarTrigger` comes from [Sidebar](/docs/components/sidebar), which the block doesn't install. Add it with `shadcn add @kosmos/sidebar`, or leave `leading` out when the page has no sidebar.

The header holds the state; your page does the filtering, as above. Pass the page body as `children`: it becomes the panel of the selected tab, so screen readers hear which view it shows. Every value (tab, search text, filters) works controlled, with its `on…Change` callback, or keeps its own state when you leave it out. The tabs and filters at the top of the file are sample data.

## What it does

- **Title and description**: the description says in one line what the page lists. Both wrap instead of cutting off.
- **Views**: the tabs sit in a track, each with an optional count, and scroll sideways when they don't fit.
- **Filter menu**: options that share a `group` sit under its name. Within a group, filters usually widen the list (Pro or Scale); across groups they narrow it (Pro and iOS). That logic is yours, in the page.
- **Chips**: each filter that is on shows as a chip under the toolbar, named with its group. Removing one moves focus to the next chip, or back to Filter.
- **Width**: the header lays itself out by its own width, with container queries, not by the screen's. From 768px wide the tabs and the search share a row; narrower, the search moves under the tabs. Below 448px the primary action and Filter shrink to icons.
