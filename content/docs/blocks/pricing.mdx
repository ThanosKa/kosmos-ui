The block brings [Segmented control](/docs/components/segmented-control), for the switch, [Badge](/docs/components/badge) and [Button](/docs/components/button) with it, and lands in `components/pricing.tsx`.

## Usage

```tsx
import Link from 'next/link';
import { Pricing } from '@/components/pricing';
import { buttonVariants } from '@/components/ui/button';

export function PricingSection() {
  return (
    <Pricing
      title="Start free, pay as you grow"
      description="Pay yearly and save 20%."
      plans={[
        {
          name: 'Free',
          price: '$0',
          period: 'forever',
          features: ['1 project', '50,000 events a month'],
          action: (
            <Link href="/signup" className={buttonVariants({ variant: 'secondary', size: 'lg' })}>
              Start for free
            </Link>
          ),
        },
        {
          name: 'Pro',
          price: { monthly: '$49', yearly: '$39' },
          period: { monthly: 'per month', yearly: 'per month, billed yearly' },
          features: ['Everything in Free', '10 projects', '3,000,000 events a month'],
          action: (billing) => (
            <Link href={`/signup?plan=pro&billing=${billing}`} className={buttonVariants({ variant: 'primary', size: 'lg' })}>
              Start a trial
            </Link>
          ),
          featured: true,
        },
      ]}
    />
  );
}
```

Write each price as it should read, such as `'$49'`, so the block never guesses your currency or your rounding. A plan's `action` is yours to style: a `primary` Button on the featured plan and `secondary` on the rest, or a function that gets the billing shown, so the link can carry it. The title, line and plans at the top of the file are sample data.

## What it does

- **Billing**: when any plan has a price per billing, a switch above the plans picks monthly or yearly, and every price and period changes with it. Plans with one price keep it. With no price per billing, there is no switch.
- **Screen readers**: after the billing changes, from the switch or from your own state through `billing`, they hear it read out once, with each plan's new price, such as "Yearly. Free: $0 forever. Pro: $39 per month, billed yearly."
- **Featured plan**: one plan stands on a raised card while the others sit recessed beside it, so it stands out by depth rather than by color.
- **Lined up**: names, prices, feature lists and links line up across the plans, and each link sits at the foot of its plan, however long the text above it runs.
- **Width**: the block lays itself out by its own width, with container queries, not by the screen's. Plans stack in a narrow container and stand side by side once they fit: two from 576px, three from 768px, and four in two rows that become one from 1024px.
- **Spacing**: the block sets no padding around itself. Give the section around it the space your page uses between sections, such as `pb-20 md:pb-28`, so every block on the page keeps the same rhythm.
