## Usage

Give each form its own route, and call your auth server from its handler:

```tsx
'use client';

import { useRouter } from 'next/navigation';
import { LogInForm } from '@/components/auth-forms';

export default function LogInPage() {
  const router = useRouter();

  return (
    <main className="flex min-h-svh items-center justify-center p-4">
      <LogInForm
        productName="Acme"
        links={{ 'sign-up': '/sign-up', 'forgot-password': '/forgot-password', continue: '/projects' }}
        onLogIn={async ({ email, password }) => {
          const response = await fetch('/api/log-in', { method: 'POST', body: JSON.stringify({ email, password }) });
          if (!response.ok) throw new Error("That email and password don't match. Try again, or reset your password.");
          router.push('/projects');
        }}
      />
    </main>
  );
}
```

Or keep the whole flow on one route with `AuthForms`, which switches between the views in place:

```tsx
import { AuthForms } from '@/components/auth-forms';

<AuthForms
  defaultView="sign-up"
  onSignUp={createAccount}
  onVerify={confirmEmail}
  onResendCode={sendCode}
  onLogIn={logIn}
  onResetPassword={sendResetLink}
  onSetPassword={saveNewPassword}
/>;
```

Every handler can return a promise: the form shows its loading state until it settles. Throw an `Error` to show its message, such as a wrong password or an expired code. Without handlers, the forms wait a moment and succeed, so you can try the flow before you wire it up. The product name, routes and that stand-in request are at the top of the file.

## What it does

- **Other ways in**: pass buttons as `alternatives`. They sit above the log in and sign up forms, with an "or" line under them. `AuthProviders` makes one [Provider button](/docs/components/provider-button) per provider, Google and GitHub by default. It marks the one used last time and shows a spinner while its page opens.
- **Log in**: email and password, with a link to reset the password beside its label and a link to sign up under the card. When `onLogIn` succeeds it says who logged in, with a button to continue.
- **Sign up**: name, email and a password of at least 8 characters, with your terms under the button. When `onSignUp` succeeds, `onViewChange` gets `'email-code'`, the next step. On its own route, send people to the code form from `onSignUp` instead.
- **Email code**: one box per character of the code. Pasting it, or the code autofill on phones, fills every box, and the form submits itself when you fill the last one. You can send a new code once `resendAfter` seconds have passed.
- **Forgot password**: asks for the email and sends a reset link. Then it says to check the inbox without telling whether an account uses that address.
- **New password**: the page your reset link opens. It asks for one new password of at least 8 characters, which people can show to check it, so it needs no second field. Then it says the password changed, with a button to log in. A link that has expired shows your error and a link to send a new one.
- **Email first**: `EmailFirstForm` asks one thing at a time. First the email, then the password, with a button to get a code by email instead. The email stays on screen with a Change button on both steps, and focus moves to the field of each new step.
- **On the page or in a card**: every form sits in a card. `appearance="plain"` sets it on the page itself with a larger title, for a full-page layout such as the variants below.
- **Errors**: once you submit the form, each field says what is wrong under it, and focus moves to the first field to fix. Errors from your server show above the fields, or under the code.
- **Loading**: the button shows a spinner and says what is happening, the fields can't change, and pressing the button again does nothing.
- **Keyboard and screen readers**: every field has a visible label. When a link switches the view in `AuthForms`, focus moves to its first field. When a success state replaces a form, focus moves to its title.
- **Width**: the card is at most 384px wide and fills a narrower container, with less padding below 384px.

## Variants

Each variant is a full page around the forms. Pass a form as `children` to use it on its own route, such as `<AuthBackdrop><LogInForm appearance="plain" /></AuthBackdrop>`.

### Backdrop

The form stands on the page with no card, over a [Flickering grid](/docs/components/flickering-grid) that fades out toward the middle and a [Glow](/docs/components/glow) at the top. Google and GitHub sit side by side above the form, and the one used last time has a "Last used" badge.

<ComponentInstall name="auth-backdrop" />

### Split

The page in two halves. One half holds the form, with your product name above it and the legal links under it. The other holds a customer's quote and the teams that use the product. Below 896px wide, the panel goes and the form stands alone. Pass your own panel as `aside`.

<ComponentInstall name="auth-split" />

### Email first

The email first, then the password or a code sent to the email, in a card in the middle of the page. Your `onContinue` handler looks up the email and picks the next step. Return `'code'` for an account without a password, once you have sent it a code.

<ComponentInstall name="auth-email-first" />
