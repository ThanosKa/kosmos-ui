## Installation

The block brings [Dialog](/docs/components/dialog), [Field](/docs/components/field), [Input](/docs/components/input), [Textarea](/docs/components/textarea), [Select](/docs/components/select), [Switch](/docs/components/switch), [Badge](/docs/components/badge), [Avatar](/docs/components/avatar) and [Button](/docs/components/button) with it, and lands in `components/new-item-dialog.tsx`.

## Usage

```tsx
import { NewItemDialog } from '@/components/new-item-dialog';

<NewItemDialog people={team} onCreate={(values) => addToRoadmap(values)} />;
```

The dialog opens from a **New item** button and puts focus in the title field. The sample form makes a roadmap item: a title and a description, then its stage, area, assignee and target quarter. Pass your own `stages`, `areas`, `targets` and `people`, or change the fields and `NewItemValues` in the file to fit your records.

To open it from a column of the [kanban board](/docs/blocks/kanban-board), pass `trigger={null}`, control `open`, and start the form in that column. `onCreate` gets ids, so map them to what your card shows:

```tsx
<>
  <KanbanBoard items={roadmap} onItemsChange={setRoadmap} onAdd={(column) => openNew(column)} />
  <NewItemDialog
    open={open}
    onOpenChange={setOpen}
    trigger={null}
    defaultValues={{ stage: column }}
    onCreate={(values) =>
      setRoadmap([
        ...roadmap,
        {
          id: crypto.randomUUID(),
          title: values.title,
          column: values.stage,
          area: values.area ? areas[values.area] : undefined,
          assignee: values.assignee ? team[values.assignee] : undefined,
          target: values.target ?? undefined,
          votes: 0,
        },
      ])
    }
  />
</>
```

The card shows no description, so keep it for the item's own page or drop the field from the form.

## What it does

- **Validation**: submitting without a title shows the error under the field and moves focus to it.
- **Creating**: `onCreate` gets the trimmed title and description, the stage, and the area, assignee and target as ids (or `null`), then the dialog closes.
- **Create more**: with the switch on, the dialog stays open. It clears the title and description, keeps the stage, area, assignee and target, and confirms the new item.
- **Fresh form**: each time the dialog opens, the form starts from `defaultValues` again. To hold the form yourself, pass `values` and `onValuesChange`. A controlled form stays as you set it.
- **Narrow containers**: the stage, area, assignee and target selects stack in one column when the dialog is narrower than 20rem.

## Motion

The dialog grows from 95% while it fades in over 250ms, and leaves in 150ms. With the reduced motion setting on, it only fades.
